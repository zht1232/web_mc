交付到服务器上的东西，用户会**亲自进游戏看行为**、并**盯 CPU/内存占用**。"技术上跑通了"不等于合格：行为要看着像活的，常驻进程要给出实测数字（核数、ms/步），不能只说"应该没问题"。

**Why:** 2026-09-19 HiveMind 上线后连续两次被打回："看起来好傻，被方块挡住就过不去，自己还不会动"、"还是很傻，另外我的 cpu 直接跑满了"。查下来一个是行为设计问题（果蝇脑 forward 通道实测恒为 0，不加基线巡航它真的不动），一个是配置默认值问题（`threads: 0` 用满 8 核，实测反而比 2 线程慢一倍）。同期我自己还犯了两次"改完没真跑"的错：全局 sed 改品牌名把 Python 第三方库的类名 `flybrain.FlyBrain` 一起改了（`py_compile` 过了，一运行就 ImportError）；重写主类时漏掉"先释放数据再拉大脑"的时序，以及把发传感帧门控在 `isLive()` 上造成死锁——两次都让用户白重载了一轮。

**How to apply:**
- 上线前先自己端到端跑一遍真实路径（不是只编译过）：子进程要真起、数据要真加载、协议要真握手。
- 性能类默认值一律**实测后选**，别信"让库自己决定"；报告里给对照数字（如 8 线程 31ms vs 2 线程 14ms、4.12 核 → 1.1 核）。
- 生物/角色类行为要问"看着像不像活的"：静止环境下的真实数据可能等于"不动"，需要显式补基线活动，并把这个取舍讲清楚。
- 批量重命名/迁移时，**别把第三方库的符号一起改**；改完至少跑一次真实执行（import + 运行），`py_compile`/编译通过不够。
- 用户吐槽"傻/卡"时，先拿实测数据定位根因再改，别急着加功能。
- **网页游玩验收**：用户会在手机上真实下载/进服；73MB 下载进度卡死、Cloudflare Tunnel ping 高、改设置崩溃都算不合格。客户端 WASM 崩溃与中继/网络问题要分开报告；网络侧优先直连 TLS 端口，不要把 Tunnel 当最终方案。改完/重启后按公网、手机、回归、冒烟顺序复验；材质包/CraftEngine 配置未完整重启时不要假装通过。
- **云电脑/重负载验收**：真实 Java 客户端 + ffmpeg + Paper + headless 浏览器软件解码同机跑会把 4c/8t 打满；1080p High 4.2 WebCodecs 还会直接崩浏览器。不要把"起了/有帧"当通过；先看 CPU、浏览器是否崩，再决定降规格或换路径。
- **用户说“CPU 炸了 / 浏览器崩了”时**：先给**根因链和下次规避**，不要反射性把会话、子 agent 或工作停掉。若为安全必须先停，要明确说“只是停这次残留会话，工作继续”，并立刻补护栏/降规格。2026-10-31 我停了云会话和子 agent，被用户纠正：“我不是让你停，我是要为什么，下次怎么避免，没让你停工作。”
