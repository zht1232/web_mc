`webcraft26` (this workspace) is a browser WebGL2 recreation of **Minecraft Java 26.2 "Chaos Cubed"** using the user's own unpacked official assets. The bar is **1:1 per detail**, not "looks similar": he lists Steve's hand, the held-block position, the inventory block-icon angle, "等等等等", and says to read the source or take in-game screenshots.

**Why:** on 2026-11-01 he played it and said it "看起来就像个劣质的游戏" with four concrete defects — first-person arm wrong, shadows flicker while moving, lake has missing textures, movement only works by flying — and told me to work without budget limits. He then added two standing requirements: research agents must inventory **what is implemented vs what remains** (not just detail fidelity), and the shader/lighting look must come from **unpacking Complementary Reimagined**, not from my own approximation. See [[feedback-copy-reference-not-improvise]].

**Acceptance bar for anything visual:** capture our output and compare it side by side with a real vanilla reference — per feature (AO gradient, hand scale and sway, light falloff, water tint and waves, cloud layer, UI layout), never per-pixel terrain, because our generator is not vanilla's. A working vanilla client for reference captures exists; see [[reference-mc262-authoritative-data]].

**Verified state of the project as of 2026-11-01 (from a code-evidence audit; re-check before relying on it):**
- It is effectively a **creative-mode renderer + menu shell**, not a survival game: no item/stack model (hotbar is `BlockDef[9]`), fixed 13×13-chunk world with full-height columns and no streaming, no world tick, no persistence, no drops/crafting/containers/hunger/XP, game mode ignored.
- **M1's offline half is built and validated** — `scripts/vanmodel.mjs` ports FaceBakery/FaceInfo/Quadrant/OctahedralGroup/BlockMath/TextureSlots, `scripts/build-states.mjs` bakes every blockstate and self-tests against the measured inventory, `scripts/statepack.mjs` writes the quantised binary. Output: `public/mc/states.json` (1.38 MB, 1,198 blocks / 7,296 variant keys / 1,132 multipart entries) + `public/mc/states.bin` (3.20 MB, 6,816 models / 67,566 quads / 1,230 face textures). **`src/` still does not consume it** — M1c is the runtime switchover, and the atlas only ships 103 of those 1,230 textures.
- Several things look implemented but are dead: hardness data (nothing reads it — every block breaks in one click, bedrock included), `rain.png`/`snow.png`/`vignette.png`, XP/offhand sprites, `tab_item_search.png`, furnace/crafting/chest GUI textures all loaded with no consumer, the survival-inventory tab is a hit-test shell, four creative categories are empty arrays, multiplayer has a real Paper plugin but **zero `WebSocket` in `src/`** (Join shows a scripted progress message), and Create-New-World only toasts (the world is generated with a hardcoded seed before the menu closes).
- **Assumptions measurement overturned** (do not re-assert them): multipart is not an edge case — 102 files / 1,132 entries is a workhorse (fences, panes, walls, redstone wire, fire, vines), so a variant dispatcher alone does *not* cover 90%; `weight` is essentially unused (0 hits in variants; randomness comes from repeated array entries); `CombinedCondition` has no `INVERT` operator in 26.2; `CuboidFace` has no `uvlock`/`uvscale` fields (uvlock exists only on blockstate variants); `builtin/generated` item sprites are gone (1 of 1,271) — items are the `items/*.json` component layer.
- 26.2 adds per-element `light_emission` and a second emissive slot (`cross_emissive`), and torch models hold **only the post element** — the flame is not block geometry, so it must come from that emissive layer.

**Build order agreed from the gap reports** (tasks #19-#29): M1 blockstate+model pipeline → M2 item/stack/components → M3 survival loop (mining time, crack overlay, drops, crafting, containers, hunger/XP, game modes) → M4 infinite streaming chunks + persistence → M5 structures from the 1,212 official NBT templates → M6 jar-derived lightmap/sky/sun-moon/cloud/fog/weather → M7 mob models/AI/spawn rules → M8 multiplayer client for the existing Paper bridge → M9 full GUI screens, lang table, particles, audio → **M10 port Complementary Reimagined's lighting and post pipeline** → **M11 the vanilla screenshot-comparison harness and acceptance pass**. **M6 and M10 are deliberately pulled forward** because neither depends on M1 and both are the biggest contributors to the "cheap game" impression.

**How to apply:**
- Before proposing work, check it against this order — anything needing real block states or item stacks is blocked on M1/M2.
- Ground truth for every number comes from the local official files or the real game, not memory. See [[reference-mc262-authoritative-data]] and [[feedback-verify-claims-before-recommending]].
- **Verifying in the Qoder embedded browser**: dev server runs `vite --host 0.0.0.0 --port 5174` (LAN address seen as `192.168.3.85`). `http://127.0.0.1:5174/?preview` bypasses the main menu; `&quality=low|medium|high|ultra` forces a profile. The embedded browser **cannot obtain pointer lock**, so player input stays gated — instrument through `window.__mc` (`player, world, renderer, hud, mobs, mobRenderer, particles, audio, openInventory, setTicks, setQuality, setRenderDistance`), e.g. set `player.locked = true` to exercise physics and set `player.pos/yaw/pitch` to frame a screenshot. GPU there is a real GTX 1050 Ti (ANGLE/D3D11), viewport ~718×772, ~29 FPS while agents build.
- World generation + meshing takes 10-25 s alone and several minutes while many agents run concurrently, and shader-compile errors surface only as a `Load failed:` label on the loading screen — poll `window.__mc` rather than assuming the page is alive. See [[feedback-subagents-encouraged]].
- Work without budget limits but keep conclusions as a prioritised list. See [[feedback-unlimited-effort-autonomy]], [[user-profile]].
