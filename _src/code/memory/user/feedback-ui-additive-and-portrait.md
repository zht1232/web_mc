既有页面的 UI 改造默认是**增量**：保留现有布局、配色、导航和 CSS，只在现有页面/卡片旁边加一个元素；不要把整页重画成自己的新方案。手机竖屏必须保留完整视觉动效，不能退化成平铺版。

**Why:** 2026-10-25 用户要首页加“多实例展板”，我拿一个全新的双卡页面做预览，他强烈反弹：“？？？？，我要我原来的布局，没让你乱改css，我要在原来的主页布局上多加一个卡片而已！！！！原来主页不是有一个液态玻璃卡片了吗其他什么都别动”。改用“当前首页截图 + 同款液态玻璃卡 + 三个摆放位置对比”后才通过；之后他又明确要求“双展板记得竖屏兼容，竖屏不要阉割效果”，并在手机缓存到旧 `home.js`、只看到一张卡时立刻指出“竖屏我这里只显示了一个展板”；同一天公网 Wiki 仍旧，根因也是 `live.js` 没升 `?v=`。

**How to apply:**
- 先拿用户当前页面的真实截图/现状做底，新元素复用现有材质、字体、间距、圆角；只加一个卡片/面板，不改现有 nav、hero、卡片和页面高度。
- 设计预览给“现状截图 + 新元素不同摆放位置的截图对比”，并说明每处会压到什么；不要把新布局直接说成最终稿。
- 竖屏/手机保留完整效果：3D 倾斜、透视、液态玻璃、双层背板都要在，不要用平铺列表代替；在 390/430 宽度实测无横向溢出、无裁切。
- 改任何 index 里带 `?v=` 的入口资源（home.js、live.js、wiki.js 等）后必须同步升版本号；HTML 是 no-store，但旧脚本 URL 仍会命中浏览器缓存。必须用全新浏览器在**公网域名**上确认新页面；本地 fresh context 会掩盖缓存问题。
- 通过后只提交“新增卡片”本身，不要顺手重构相邻区域。
